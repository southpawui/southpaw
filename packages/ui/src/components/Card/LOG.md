# Card — Change Log

## 2026-11-10 — Icon, HeaderAction, /improve fixes

### What changed

- Added `Card.Icon` sub-component — leading icon above title in header (Carbon, Primer pattern)
- Added `Card.HeaderAction` sub-component — action slot pinned top-right in header (shadcn pattern)
- Header is now always `grid auto-rows-min` (shadcn approach) — HeaderAction uses `col-start-2 row-span-2 row-start-1 self-start justify-self-end`
- Icon uses `col-span-full` removed — just flows naturally in col 1 above title
- Fixed CardImage ref type mismatch: wrapper is `HTMLDivElement`, props separated for wrapper vs img
- Fixed `data-interactive` to render `""` instead of `"true"` (consistent with other data attributes)
- Added 3 tests: direction prop, Action sub-component, data-interactive attribute
- Added comment explaining flex-col + grid coexistence

### Why

- **Card.Icon above title**: User preferred stacked layout (icon above title) over side-by-side. Most dashboard cards use this pattern. The icon establishes context visually before reading the title.
- **Card.HeaderAction**: shadcn recently added this. Eliminates need for absolute positioning or wrapper divs. Grid `has-[data-slot]` conditional columns handle all cases automatically.
- **Always-grid header**: shadcn's approach — header is always grid. Simpler than conditionally switching between flex and grid. `auto-rows-min` prevents empty rows.

### Considered and rejected

- **Icon beside title (side-by-side)**: Built it first, user preferred stacked. Side-by-side felt like a list item, not a card header.
- **Conditional flex/grid on header**: Original approach used `has-[]` to switch between flex-col and grid. Complex and fragile. shadcn's always-grid with conditional columns is cleaner.
- **row-span-full / span 99 on HeaderAction**: Created 99 implicit rows, stretching cards. Fixed with explicit `row-span-2` matching shadcn.

## 2026-11-10 — Full enhancement

### What changed

- Added `variant` prop: elevated (default, shadow), outline (border only), filled (solid bg, transparent border)
- Added `interactive` prop: border highlight on hover + scale press feedback from centre origin
- Added `direction` prop: vertical (default) / horizontal (image on side, responsive — stacks on mobile)
- Added `Card.Eyebrow` sub-component — small uppercase label above title (Carbon, Primer pattern)
- Added `Card.Action` sub-component — text affordance for interactive cards (muted → default on card hover)
- Added `Card.Image` sub-component — absolute-positioned img in a relative wrapper for both layouts
- Added `data-interactive` attribute on Root for CSS targeting (image zoom only on interactive cards)
- Image zoom on hover: 5% scale, 250ms slow duration, only on interactive cards
- Footer responsive: buttons go full-width on mobile via `[data-slot=button]` selector, badges stay inline
- Footer `mt-auto`: pushes to bottom of card in grid layouts (uniform footer alignment across a row)
- Footer conditional `pt-6`: when no Card.Content sibling exists, via `:not(:has())` selector
- Filled variant: transparent border that reveals on interactive hover
- Horizontal direction: CSS grid with `grid-cols-[auto_1fr]` at sm+, stacks on mobile with `h-48` image
- Horizontal image spans all rows via `grid-row: 1 / span 99` (implicit rows don't support `-1`)
- 14 unit tests, 7 stories (Default, Variants, Interactive, WithImage, Horizontal, Themes)
- 0 a11y violations

### Why

- **Variants**: Chakra and MUI both offer outline/elevated/filled (2/8). Essential for visual hierarchy — elevated for primary content, outline for secondary, filled for grouped/background content.
- **Interactive**: Chakra, MUI, Spectrum (3/8) offer clickable cards. Border highlight + scale is cleaner than shadow bump — per user preference, no translate-y movement.
- **Direction**: MUI has horizontal CardMedia, Carbon has HorizontalCard. Common for list views, blog posts, product listings.
- **Eyebrow**: Carbon has dedicated `CardEyebrow`, Primer has `EyebrowBanner`. All 8 libraries support the pattern in some form. Small, uppercase label indicating category/type.
- **Card.Action vs Button**: When the whole card is interactive, a button inside creates confusing double-hover. Card.Action is a visual affordance (text + icon) that responds to the card's hover state, not its own.
- **Footer mt-auto**: Without this, cards in a grid row have misaligned footers when content heights vary. `mt-auto` in a `flex-col` parent pushes footer to bottom.
- **Footer button targeting**: `*:w-full` was making badges and text spans full-width on mobile. Switched to `[data-slot=button]` selector to only target buttons.
- **Image span 99**: CSS Grid's `row-span-full` (row: 1 / -1) only works with explicit rows. Our rows are implicit (auto-generated by Header/Content/Footer), so `-1` doesn't reach the end. `span 99` is a reliable workaround.
- **Mobile horizontal stack**: At narrow viewports, side-by-side cards become illegible. Stacks to vertical with `h-48` matching the vertical card image height.

### Considered and rejected

- **Shadow bump on hover** — User didn't like the translate-y bounce effect. Replaced with border highlight + scale from centre.
- **Card.Button sub-component** — Considered for suppressing button hover inside interactive cards. Decided Card.Action (plain text affordance) is cleaner — the card is the click target, not the button.
- **Elevation prop (shadow levels)** — Only MUI (1/8) has this. The three variants (elevated/outline/filled) cover the use cases.
- **Divider between sections** — Only MUI (1/8). Consumers can use Separator component inside Card.Content.
- **aspect-video for mobile horizontal images** — Tried this but it calculated different heights than vertical card's h-48. Switched to explicit h-48 for consistency.
