## Usage

```tsx
import { Button } from "@/components/southpaw/components/Button/Button";
import { Dialog } from "@/components/southpaw/components/Dialog/Dialog";

<Dialog.Root>
  <Dialog.Trigger render={<Button variant="solid" />}>Edit profile</Dialog.Trigger>
  <Dialog.Portal>
    <Dialog.Backdrop />
    <Dialog.Popup>
      <Dialog.Header>
        <div>
          <Dialog.Title>Edit profile</Dialog.Title>
          <Dialog.Description>Make changes to your profile here.</Dialog.Description>
        </div>
        <Dialog.CloseButton />
      </Dialog.Header>
      <Dialog.Body>{/* content */}</Dialog.Body>
      <Dialog.Footer>
        <Dialog.Close render={<Button variant="solid" />}>Save changes</Dialog.Close>
      </Dialog.Footer>
    </Dialog.Popup>
  </Dialog.Portal>
</Dialog.Root>;
```

## When to use

<Guidance type="do">

- A short, self-contained task that needs the user's full attention, such as editing a record or filling in a short form.
- Information the user has to read before they carry on, such as terms they must accept.
- A task the user starts from the current page and returns to it afterwards.

</Guidance>

## When not to use

<Guidance type="dont">

- **Confirming a destructive or irreversible action.** Use Alert Dialog. It needs an explicit choice and can't be dismissed by clicking outside.
- **Long or multi-step flows.** Give them their own page, so they can be bookmarked, shared and navigated with Back.
- **Content the user needs to compare with the page behind.** A modal hides the page. Use a Drawer or an inline panel.
- **Non-blocking messages,** such as "Saved". Use a Toast.
- **Errors in a form.** Show them next to the field and in an Error Summary, not in a pop-up.

</Guidance>

## Sizes

`size` on `Dialog.Popup` sets the maximum width. Choose it by content, not importance: `sm` for a sentence and two buttons, `md` (the default) for a short form, `lg` for wider forms. `full` fills the viewport. On narrow screens every size except `full` is meant to keep a 1rem margin (see [known issues](#known-issues)).

<ComponentPreview name="dialog-sizes" title="Dialog sizes" />

| Size   | Max width | Use for                                |
| ------ | --------- | -------------------------------------- |
| `sm`   | 384px     | A short message and one or two actions |
| `md`   | 448px     | Default. Short forms                   |
| `lg`   | 512px     | Forms with longer fields               |
| `full` | Viewport  | Dense tasks on small screens           |

Dialog has no colour variants. A dialog is a neutral surface (`surface-overlay`). Its actions carry the intent: brand for the main call to action, danger lives on Alert Dialog.

## Content guidance

### Title

Say what the dialog is for, in a few words. Use sentence case and no full stop.

<ContentRule do="Edit profile" dont="Profile Editing Dialog." />

### Description

One sentence that adds something the title doesn't. Leave it out rather than repeat the title.

<ContentRule
  do="Make changes to your profile here."
  dont="This dialog lets you edit your profile."
/>

### Buttons

Name the main action with a verb that says what happens, and match the title where you can. Put it last; it shows first on mobile.

<ContentRule do="Create project / Cancel" dont="OK / Cancel">
  "OK" doesn't say what will happen. Users scanning the buttons should know the result without
  reading the body.
</ContentRule>

You don't need a Cancel button when the only way out is closing: the × button, Escape and clicking outside all close the dialog.

### Focus

- When the dialog opens, focus moves to the first focusable element inside it. Change this with `initialFocus` on `Dialog.Popup`.
- Focus is trapped: Tab never reaches the page behind.
- When the dialog closes, focus returns to the trigger. Change this with `finalFocus`.
- The page behind is inert while a modal dialog is open, and it can't scroll.

### ARIA

- `Dialog.Popup` has `role="dialog"` and `aria-modal="true"`.
- `aria-labelledby` points at `Dialog.Title`, and `aria-describedby` at `Dialog.Description`. Always render a title.
- `Dialog.CloseButton` has the accessible name "Close".
- The trigger gets `aria-haspopup="dialog"` and `aria-expanded`.

### Known issues

- **On phones the dialog touches the screen edges.** The 1rem mobile margin is meant to keep it clear of the edges, but it is currently overridden by the size's maximum width. This has been reported and a fix is pending.
- **Very tall content can overflow the viewport.** The popup has no maximum height of its own. Cap `Dialog.Body` (for example `max-h-[60vh]`) when content might be long.
- **The close button has no tooltip yet.** Southpaw's rule is that every icon-only button gets one. Its accessible name, "Close", is in place.
- **Nested dialogs** work (Base UI supports them) but have no example yet.
